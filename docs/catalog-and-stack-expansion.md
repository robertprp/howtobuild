# Mobile catalog and optional SaaS capabilities

Research checked September 6, 2026. This batch adds twelve reviewed mobile projects to the six existing entries. It adds capabilities to the starter prompt, not live billing or identity verification to HowToBuild itself.

## Discovery and indexing

GitHub repository search was run for React Native and Flutter topics, filtering archived repositories and recent pushes. A second search finds repositories created in the last 49 days. Search results include tutorials, lists, and finished consumer apps: they require editorial review, not automatic publication.

Total stars and recent pushes are discovery signals, **not seven-week star growth**. New catalog entries receive an actual first snapshot, remain without historical growth until there is enough evidence, and join the existing daily collector. The configured Vercel schedule is 03:17 UTC; it requires the deployed job configuration and credentials. Running a local development server does not execute that schedule.

Commands (load the existing `.env`; never initialize a database):

```sh
node --env-file=.env --import tsx scripts/discover-github.ts react-native
node --env-file=.env --import tsx scripts/discover-github.ts flutter
node --env-file=.env --import tsx scripts/import-mobile-projects.ts
node --env-file=.env --import tsx scripts/import-mobile-projects.ts --apply
node --env-file=.env --import tsx scripts/sync-github.ts
```

Discovery is read-only, bounded to two searches of thirty candidates each, and emits JSON to stdout. The import defaults to a dry run. `--apply` inserts reviewed content into the configured existing database and collects snapshots. Existing project slugs are never overwritten or republished; each new project and its links/sources/facets commit together. On failure, earlier completed entries remain; rerunning is safe. No new migration is needed. Review and extend the checked-in manifest before another batch; do not feed arbitrary search descriptions directly into publication.

## Optional stack categories

Available on Modern TypeScript SaaS, AI SaaS, and Open-Source SaaS. Not added to the infrastructure-only observability stack. All start as **Not needed**, appear in compact expandable sections, and are excluded from the copied/downloaded prompt until selected. Existing framework-specific authentication and styling choices retain their compatibility gate.

| Responsibility              | Researched choices                                                                                                                                                                         | When to choose                                                                                                                                                                                                                                                                                                                                                                                              |

For non-Next frameworks, use their current official integration.                                                                                                                                                                                         |

KYC, KYB, AML screening, age assurance, and sign-in are not interchangeable. A provider integration does not establish legal compliance. Hosted verification reduces direct handling of documents; approval must come from verified server-side outcomes, never a redirect query parameter. Provider eligibility, retention and any jurisdiction-specific obligations need product-owner review. Do not send identity data to analytics.

Hosted add-ons deliberately remain optional on the open-source stack: enabling one changes its original ownership and operating-cost assumptions. Numeric prices are not embedded because usage mix, country, and contracts vary. No provider subscriptions, accounts, or paid infrastructure were created by this change.
