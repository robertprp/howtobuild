## Selection behavior

Optional capabilities remain “Not needed” until selected and do not appear as selected technologies in the copied or downloaded prompt. Framework/database-dependent groups are recomputed from the effective selections. Switching away from TanStack removes its auth integration guidance; switching to an unsupported documentation framework hides Fumadocs and excludes it from the prompt. Hidden selections may be restored when switching back to a compatible framework.

Open-Source SaaS retains its existing separate API layer when TanStack is selected. The prompt requires an explicit boundary rather than silently deleting that API choice. Hosted add-ons change the baseline stack's ownership and cost assumptions. The observability-only stack is not given unrelated SaaS demo/ORM/framework choices.

## pnpm policy

Generated TypeScript instructions require pnpm for dependency installs, scaffold commands, scripts, examples, documentation and CI. They request a compatible pinned `packageManager`, a committed `pnpm-lock.yaml`, and `pnpm install --frozen-lockfile` in CI. They forbid npm/npx/Yarn/Bun package-manager commands without conflating a runtime choice with its package manager. Existing non-pnpm work must not be destructively migrated without approval. The HowToBuild repository already uses pnpm; no dependency or lockfile migration was needed here.

These are sourced integration suggestions, not certification that every arbitrary version combination works. Verify pinned versions, provider accounts and deployment adapters before building the resulting application.
